# 阶段 A · 数据源体检 —— 面试问答（淘宝 UserBehavior 离线数仓）

> 批改标准：**先划范围 → 再给证据 → 最后给边界**。
> 铁律：**每个数字都要能说出它从哪来，说不出来就是编的。**

---

## 0. 通用答题框架

| 步骤 | 做什么 | 反面 |
|---|---|---|
| ① 划范围 | 先声明口径：全量还是窗口内？行还是人？ | 上来就报数，口径全靠对方猜 |
| ② 给证据 | 报精确数字 + 说清怎么算的 + 有第二条路印证 | "大概""差不多""几万条" |
| ③ 给边界 | 这个数**不能**回答什么 | 把结论说得比数据能支撑的更大 |

## 第 1 题：你怎么证明自己没算漏？

### 1.1 三个必须会的概念

**① 总量锚点** —— 拿一袋标着 1kg 的米去校秤

一个**不来自我这条流水线**的、事先就知道的数，用来钉住结果。

| 锚点 | 值 | 为什么它不来自流水线 |
|---|---|---|
| 文件字节数 | 3,672,347,465 | 文件属性就能看 |
| MD5 | 2c67e9b4e3908fd30a3f43ec95a7de8c | 官方给的，且已校验一致 |
| 行数 | 100,150,807 | 用 Spark 和裸 Python 两种方式各数了一遍 |

**为什么必须有**：如果 `header` 写错、把首行当表头吃了，**我所有的数会一起少 1 行，内部对账全部通过**——因为错得一致。只有外部锚点能发现。

> 秤自己坏了，称十次取平均也没用。得拿标着 1kg 的米去校。

**② 守恒律** —— 进货 100 斤 = 出菜 80 + 边角料 15 + 损耗 5

输入必须等于所有输出之和，中间不许丢东西。

| 守恒式 | 实际数字 | 证明了什么 |
|---|---|---|
| 四种行为行数之和 = 总行数 | 89,716,264 + 5,530,446 + 2,888,258 + 2,015,839 = **100,150,807** | 没有第五种行为，也没有解析漏行 |
| 窗口内 + 窗口外 = 全量 | 100,095,231 + 55,576 = **100,150,807** | 时间过滤没丢数据 |
| 越界四类之和 = 越界总数 | 52,830 + 2,398 + 318 + 30 = **55,576** | 分类穷尽，没有"其他"藏东西 |
| DWD 主表 + 坏记录表 = 全量 | 待兑现 | 阶段 C 的验收标准 |

**③ 独立路径复算** —— 算盘算一遍，计算器算一遍

用**完全不同的工具、完全不同的代码**算同一个数，一致才可信。

```
路径 A（Spark）    ：01_profile.py 段5，算窗口内  = 100,095,231
路径 B（裸 Python）：流式逐行扫，算越界         = 55,576
                    ↓
    100,150,807（锚点） − 100,095,231 = 55,576 ✓
```

**关键**：必须"不同"。**同一份代码跑两遍只证明结果稳定，不证明结果正确。**

### 1.2 我的原始回答

> 完全不会，不理解"总量锚点""守恒律""独立路径复算"这些词。

**批改：0 / 3。** 这不是能力问题，是这三个词从没学过。

### 1.3 标准答案（背这四句）

> 「**三条证据，缺一不可。**
> **第一，总量有锚点**：文件 3,672,347,465 字节、MD5 与官方一致，行数 100,150,807 是用 Spark 和裸 Python 两种方式各数了一遍，结果一致——如果只有一套代码，它错得再一致我也发现不了。
> **第二，守恒成立**：四种行为的行数相加正好等于总行数，说明既没有第五种行为、也没有解析漏行；窗口内 100,095,231 加窗口外 55,576 也正好等于全量。
> **第三，独立路径复算**：Spark 算窗口内总量，裸 Python 流式扫越界行数，两个数相加回到全量，两条完全不同的代码路径走到同一个结果。
> **所以我敢说算干净了——不是因为我仔细，是因为每一条结论都有第二条独立的路验证过。**」

### 1.4 可能的追问

| 追问 | 怎么答 |
|---|---|
| 你数据量才 1 亿，有必要这么较真？ | 数据量大小不改变对账的必要性；**错得一致**是最贵的事故，因为它不报警 |
| 重跑两次结果一样，不就说明对吗？ | 不一样。重跑同一份代码只证明**稳定**，bug 会稳定地复现。要证明**正确**必须换一条独立的路径 |
| 你怎么知道锚点本身是对的？ | 锚点也分级：文件字节数是操作系统给的、MD5 是官方给的、行数是两条路径互证的。**锚点越"外部"，可信度越高** |

## 第 2 题：越界的脏数据，为什么不 filter 掉？

### 2.1 我的原始回答

> 这里面可能包括越界和负数，然后越界的数据可能是正常行为，而保留下来可以为后面的数据清洗留证据。

**批改：2 / 3。** 骨架完全对——抓住了"**框外 ≠ 垃圾**"和"**留证据**"。缺三样：

1. **没有数量**：说"5 万条"和说"55,576 条、占 0.0555%"是两种人
2. **没有分类穷尽**：没说是分几类、相加对不对
3. **没点破不可逆**：删掉是销毁，"脏"是判断不是事实

### 2.2 标准答案

> 「**不删，因为"脏"是我的判断，不是数据的事实。**
> **先分类**：55,576 行占 0.0555%，分四类——早于窗口 52,830、晚于窗口 2,398、负数 318、超过 2×10⁹（约 2037 年）的 30 行。**四类相加正好等于 55,576，说明分类穷尽。**
> **再看性质**：这 55,576 行 **100% 是 pv**，涉及 **41,450 个用户**，其中约 4 万行是 2017-11-24 的真实浏览记录，只是不在我的分析窗口内——它们是"框外"，不是"垃圾"。
> **所以隔离不删除**：搬进 `dwd_bad_record`，保留原始五列，另加 `bad_reason` 记录排除原因。
> **代价**是我多维护一张表；**收益**是报表对不上时我能立刻回答"少的那 4 万在隔离表里，不是 bug 丢的"，而且哪天要扩大窗口，它们能捞回来。**守恒式：主表 + 坏记录表 = 100,150,807。**」

### 2.3 可能的追问

| 追问 | 怎么答 |
|---|---|
| 那 4 万行 11-24 的，你为什么不把窗口放大？ | 数据分析窗口由业务问题定义（11-25 起 9 天），不是由数据边界定义；**放大窗口会污染"日均"口径** |
| `dwd_bad_record` 后面会有人看吗？ | 平时不看，**出事第一个看**。它是我的责任证据 |
| 你凭什么判断"越界"而不是"代码解析错位"？ | 字段数≠5 的行 = 0，四种行为之和 = 总行数——**结构上没掉行，所以不是解析问题** |

## 第 3 题：购买率是 2% 还是 68%？转化率提升了多少？

### 3.1 我的原始回答

> 如果购买率是购买的人数/总人数那就是 68%，而那 2% 是购买行为/总行为。后面的问题答不上来。

**批改：1 / 3。** 第一问对一半（措辞要改），第二问是深坑，没答。

### 3.2 第一问：两个都对，口径不同

```
2.01%  = buy 行数 2,015,839 ÷ 总行数 100,150,807       ← "行为构成"口径
68.06% = 买过的去重用户 672,404 ÷ 全部去重用户 987,994  ← "用户覆盖"口径
```

**措辞纠正**：不要说"总人数"——总人数是谁？注册用户？活跃用户？**必须说清谁当分母。**

> 「**两个都对，但口径不同，差 34 倍。说"购买率"第一句必须带口径，否则就是误导。**」

**附带发现**：**漏斗倒挂**——fav 用户 389,823（39.46%）低于 buy 用户 672,404（68.06%）。行口径无倒挂（89.7M > 5.5M > 2.9M > 2.0M，完美台阶），**换成人就倒挂了**。这是"行 ≠ 人"的终极证据。

### 3.3 第二问：这个坑叫"冒领功劳"

面试官问「**你把转化率提升了多少**」，话里埋了个假设：**你做的东西改变了用户行为。**

**而我没有。**

| 我改变了的 | 我没改变的 |
|---|---|
| 取数速度 | 用户的下单意愿 |
| 口径一致性 | 商品的曝光 |
| 分析门槛（不会 SQL 也能问） | 转化率本身 |
| 结果可追溯（evidence 字段） | — |

> 说"我提升了转化率"，等于说"我在村里修了条路，所以今年收成好"。

**技术上也不成立**：证明"提升"需要**对照组**（A/B 实验）或**干预前后同口径对比**，两样都没有。

### 3.4 标准答案

> **问：购买率是 2% 还是 68%？**
> 「**两个都对，口径不同。** 2.01% 是 `2,015,839 ÷ 100,150,807`，算的是**行为构成**——买这个动作只占全部行为的 2%；68.06% 是 `672,404 ÷ 987,994`，算的是**用户覆盖**——买过东西的人占全部去重用户的 68%。**同一天的数据换个分母差 34 倍，所以我说购买率第一句永远是"哪个口径"。**」
>
> **问：你把转化率提升了多少？**
> 「**这个我不能说，因为我没有资格说。**
> 我做的是**离线数仓 + AI 分析层**，它改变的是**取数效率和口径一致性**，**它没有改变任何一个用户的购买决策**——所以"转化率提升"这个因果，我证明不了。要证明它需要 A/B 实验或干预前后同口径对比，两样我都没有。
> **我能量化的是分析侧**：原来查一个指标要手写 SQL、口径靠人记、错了没人知道；现在 ADS 层固化口径、NL2SQL 秒级响应、每条结论强制带 evidence 字段、30 条评测集做回归。
> **业务价值方面，我给的是"洞察候选"，不是"已验证的效果"。这个界线我分得清。**」

### 3.5 可能的追问

| 追问 | 怎么答 |
|---|---|
| 那你这项目到底有什么价值？ | 价值在**分析侧可量化**：口径固化、响应从分钟级到秒级、结论可追溯、评测集防回归。业务价值我只给"候选洞察" |
| 68% 购买率你觉得正常吗？ | **不正常**，真实电商 1–5%。说明这份公开集是筛选/抽样过的样本，**所以绝对转化率我不外推，只做相对比较**（比如 12-02 比 11-25 高多少） |
| 你怎么知道是抽样而不是真的？ | 三条：68% 购买率 + 3,880 人零 pv 却有其他行为 + 漏斗人口径倒挂。三项同时成立，只能是样本性质，不是业务事实 |
